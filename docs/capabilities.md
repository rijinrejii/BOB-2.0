# Runtime Capabilities — Review Copilot V2

Generated by: manual inspection and environment probing during ABY implementation.
Last updated: 2025-01-25

---

## How to read this document

Each capability entry lists:
- **Status**: `available`, `unavailable`, or `unverified`
- **Evidence**: what was actually checked to determine that status
- **Limitations**: known gaps or caveats
- **Operator config**: what an operator must provide to enable the capability

Capabilities are reported honestly. Where a check was not run, the status is `unverified`.
Where a restriction cannot be enforced, the capability is `unavailable` — not silently degraded.

## Concurrency and recovery

| Capability | Status | Evidence | Limitations |
|---|---|---|---|
| Concurrent resume protection | **available** | SQLite `BEGIN EXCLUSIVE` transactions used for stage transitions; `worker_id` column enforces single-worker execution | SQLite's single-writer model is relied upon; do not use a network filesystem for the store |
| Interrupted run recovery | **available** | On startup, `running` executions are marked `interrupted`; stage checkpoints are loaded from committed state | Recovery reads committed SQLite state only; uncommitted work is not recovered |
| Transactional checkpoints | **available** | Stage output is written in a transaction before the run record advances | Partial stage output is not committed |

## Unsupported capabilities (by design)

The following will never be implemented in this system:

- Automatic PR approval or merge
- Bypassing branch protection rules
- Autonomous patch application without explicit human approval
- Arbitrary shell execution from reviewed content
- Web server, dashboard, or multi-tenant service
- Kubernetes deployment or microservice architecture
- Vector database or embedding-based retrieval
- Claiming comprehensive security assurance

---

## Known limitations

1. **Windows path handling**: Git output uses forward slashes; paths are normalized. Absolute paths with drive letters are rejected for security.
2. **SQLite single-writer**: The store must not be placed on a network filesystem. Multiple review-copilot processes against the same store are serialized by SQLite write locks.
3. **Secret redaction is not exhaustive**: Patterns cover common formats. Assume any log file may contain sensitive data.
4. **Sandbox is unavailable**: Without a verified isolation boundary, verification checks are not run. This is permanent until an operator provides a verified container runtime.
5. **GitHub publication is unverified**: The adapter is implemented but has not been tested against the live GitHub API.
6. **Node.js 24 is post-LTS**: The engine runs on Node 24. Minimum requirement is Node 20. No incompatibilities observed.
